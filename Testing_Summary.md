# Data Quality Testing Summary

Generic tests provide reusable checks for common data-quality rules such as uniqueness, null values, accepted values, and referential integrity. The unique and not_null tests protect the primary keys of staging and marts models. The accepted_values test checks that order statuses remain within the expected business-defined list. The relationships test ensures that every customer referenced by the revenue fact table exists in the customer dimension. The singular assert_positive_revenue test implements a model-specific business rule that revenue must always be greater than zero. The custom non_negative test provides reusable logic that can be applied to numeric columns across multiple models. The warning-severity status test provides visibility into unexpected statuses without immediately blocking the pipeline. Together, these tests cover structural integrity, referential integrity, reusable numeric validation, and business-specific rules.
